Project: TCP over UDP
Tyler Schill and Basil Lone


        TCP applies a three-way handshake where the sender and receiver both acknowledge that they are communicating with one another before sending data. This way, the sender can ensure that their packets make it to the destination. Additionally, TCP keeps packets in the order that they were sent, controls how many packets can be sent at a time so as not to overwhelm a network, and has error-handling mechanisms for resending packets that were dropped. UDP, on the other hand, simply sends packets to their destination. There is not guarantee that it will reach the receiver, or that packets will be sent in order. TCP over UDP attempts to implement the reliability and organization that TCP provides using the minimal framework of UDP.
        This project serves the many applications that rely on data being transmitted consistently and in order. For example, email applications need a TCP-like connection because they need all contents of an email to make to the recipient, as well as be in order (it would be hard to read an email if all of the sentences were jumbled up). 
        We plan to put this into practice by sticking the fields found in a TCP header into the data section of a UDP datagram. What this means is that after the 8 bytes that make up the UDP header, we will put TCP fields like sequence number, acknowledgement number, and flags at the start of the data portion of the packet. With the ability to send “TCP” packets, we will then create an application that mimics the network stack functionality of operating systems. It will be able to parse received packets and decide what type of packet to send in response. For instance, if the program received a packet with the SYN bit set, then it should respond with a packet with the SYN and ACK bits set to represent a SYN-ACK reply.
